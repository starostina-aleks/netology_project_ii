# Стратегии chunking


## Описание стратегий

1. **Fixed Size (Baseline)**
   - **Инструмент**: `TokenTextSplitter`
   - **Параметры**: `chunk_size=512`, `chunk_overlap=64`
   - **Особенности**: Жесткое разбиение по токенам. Не учитывает границы предложений и абзацев.

2. **Recursive**
   - **Инструмент**: `SentenceSplitter` (эквивалент `RecursiveCharacterTextSplitter`)
   - **Параметры**: `paragraph_separator="\n\n"`, адаптированная `chunking_tokenizer_fn` для русского языка.
   - **Особенности**: Рекурсивное разбиение с приоритетом сохранения целостности абзацев и предложений.

3. **Semantic**
   - **Инструмент**: `SemanticSplitterNodeParser`
   - **Параметры**: `buffer_size=1`, `breakpoint_percentile_threshold=95`, эмбеддинг-модель соответствует модели индекса.
   - **Особенности**: Динамическое разбиение на основе семантического сдвига (расстояния между эмбеддингами соседних предложений).

4. **Markdown**
   - **Инструмент**: `MarkdownNodeParser`+`SentenceSplitter`
   - **Параметры**: сначала `MarkdownNodeParser`,  затем `SentenceSplitter`, чтобы сохранить иерархию заголовков, эмбеддинг-модель соответствует модели индекса.
   - **Особенности**: удаление чанков с одной строчкой #...,  добавление структуры в текст

5. **Reranker**
   - **Инструмент**: reranker model bge-reranker-v2-m3`
   - **Параметры**: `retrieve top_k=20`

## Выводы по итогам анализа

* **Фиксированный чанкинг (`fixed_size`)** неплохие результаты
* **Рекурсивный чанкинг (`recursive`)** показал лучшие результаты
* **Семантический чанкинг (`semantic`)** самый низкий результат
* **Cтруктурный чанкинг (`markdown`)** несмотря на сложное разбиение немного  уступает рекурсивному
* **Реранкинг** значительно улучшает результаты, но очень медленный
* Выбираю стратегию Рекурсивный чанкинг с конфигом 512/64, потому что показала лучшие результаты
