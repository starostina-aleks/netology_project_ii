# LlamaIndex vs bare-metal

| Критерий | LlamaIndex                                                     | Bare-metal                                                                |
| :--- |:---------------------------------------------------------------|:--------------------------------------------------------------------------|
| Строк кода (ingestion + query, без импортов) | 104                                                            | 163                                                                       |
| Поддержка форматов из коробки | да                                                             | нет                                                                       |
| Что дописать для PDF/DOCX | ничего                                                         | parse_pdf, parser_docx                                                    |
| Что дописать для batch-ingestion / async | ничего                                                         | батчинг в store.upsert                                                    |
| Где удобнее дебажить top_score / source_nodes | Сложнее. Извлечение после ответа (через response.source_nodes) | Удобнее. Напрямую в коде после поиска в БД и до отправки контекста в LLM. |
| Где гибче подменять компоненты (re-ranker, chunker) | Ограничено абстракциями                                        | Полная свобода                                                            |****

**Вывод:**
Выбран  **LlamaIndex**
* **Быстрый старт.** Фреймворк идеально подходит для прототипирования. Он берет на себя всю рутину: сам загружает файлы, режет на куски, делает эмбеддинги, создает индекс и собирает готовый чат-движок.
* **Огромная экосистема коннекторов (LlamaHub).** Из коробки доступны сотни готовых загрузчиков данных. Можно в одну строку подключить не только PDF или DOCX, но и Notion, Discord, Slack, Confluence, Google Drive или базы данных SQL.
* **Продвинутые стратегии поиска (Advanced Retrieval).** Внутри фреймворка уже реализованы сложные механики: авто-разбиение на родительские и дочерние чанки (Parent-Child / Auto-Merging), генерация гипотетических вопросов (HyDE) и маршрутизация запросов (Router Query Engine).
