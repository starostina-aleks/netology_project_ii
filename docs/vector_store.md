### Обоснование: почему для Production выбран DOT вместо COSINE

По результатам проверки ранжирование списков `top_5_cosine_ids` и `top_5_dot_ids` полностью совпало для каждого тестового запроса. Для финальной эксплуатации в production-среде утверждена метрика **`Distance.DOT`**, так как она даёт максимальную эффективность:

1. **Математическое тождество:** В коде включена нормализация векторов (`normalize_embeddings=True`). Когда длина векторов равна $1$, формулы косинусного сходства (Cosine) и скалярного произведения (Dot Product) дают абсолютно идентичный порядок сортировки результатов.
2. **Высокая скорость на CPU/GPU:** Вычисление `DOT` аппаратно намного проще. В формуле нет деления и извлечения квадратных корней, а выполняются только операции умножения и сложения (FMA). Процессор вычисляет такие операции через векторные инструкции SIMD (AVX-512) значительно быстрее.
3. **Экономия ресурсов базы данных:** При росте коллекции до сотен тысяч документов и увеличении RPS (запросов в секунду) база данных Qdrant с метрикой `DOT` будет тратить меньше процессорного времени на обход векторного индекса (HNSW), обеспечивая меньшую задержку (Latency).
